# 番頭さん UI実装指示書 v1

**この文書の使い方**：プロジェクトの `docs/` に置き、Claude Codeに「docs/この指示書を読んで実装して」と渡す。
デザインの実物見本として `bantou-select-design.html`（チャット＋選択グリッド）も同じフォルダに置き、迷ったら見本のHTML/CSSを正とすること。

**対象範囲**：ログイン画面＋メイン画面（チャット×番頭さん選択）のUI実装。Claude APIによる生成処理の中身・DBスキーマは既存実装／別指示に従う。

---

## 0. 大原則（全画面共通）

1. **AIという言葉をUIに一切出さない。**「生成」「アップロード」「送信中」等のIT用語も使わない。ローディングは「番頭さんが考えています…」で統一
2. **高齢者向けアクセシビリティ**：本文18px以上／タップ対象は最小44px（主要ボタンは56px以上）／コントラスト比4.5:1以上／1画面1目的
3. **スマホ縦画面が主、PC・タブレットは補助**。レスポンシブのブレークポイントは 768px
4. すべての操作は**3タップ以内**で目的に到達すること

## 3. ログイン画面（/login）

- 背景：浮世絵風グループイラスト（`public/images/login-hero.png`、後日差し替え。**未配置の間は washi色ベタ＋中央に丸紋「番」のプレースホルダー**で実装を止めないこと）
- 画像は画面上部2/3に表示し、**下部1/3は washi色の帯**にして以下を重ねる：
  - 組合名（例：さくら台マンション管理組合）… 16px・墨色
  - タイトル「番頭さん」… Shippori Mincho・32px・太字
  - 一言「マンションのこと、何なりとお申し付けください」… 18px
  - 「Googleでつづける」ボタン … 高さ60px・幅いっぱい・藍色・白文字（Googleのブランドガイドに従ったGアイコン付き）
- 認証は既存のSupabase Auth（Google OAuth）フローを使用。成功後 `/` へリダイレクト

## 4. メイン画面（/）レイアウト

### 4-1. 共通ヘッダー（のれん）
- 背景 aiDeep。左に丸紋「番」（白枠円＋「番」の字）、タイトル「番頭さん」、その下に組合名（小）
- 下端に**のれんの切れ込み装飾**（見本HTMLの `.noren::after` のCSSをそのまま使用）
- 右端に**音声オン/オフの切り替えボタン**（🔊/🔇、44px、詳細は §7）

### 4-2. PC・タブレット（≥768px）：左右分割
- 左ペイン（幅約57%）：チャット＋入力欄
- 右ペイン（幅約43%）：「番頭さんを選ぶ」見出し＋**2列×3行のカードグリッド**

### 4-3. スマホ（<768px）：縦積み＋横スクロール帯
- 上：チャット（可変・主役）
- 下：番頭さんカードの**横スクロール帯**（1枚 幅108px・スクロールスナップ有効・4枚目が見切れて「まだ隣にいる」ことが伝わる状態にする）
- 帯の見出し行に「たたむ／開く」トグルを付け、たたむと帯を非表示にできる
- 最下部：入力欄

### 4-4. 番頭さんカード（共通）
- 構成：上部に帯色背景＋絵文字（将来は浮世絵イラスト画像に差し替えるため、`<Image>`に差し替えやすい構造にする）、下部に名前（例「はり出し番頭」）
- 選択中カード：墨色の太枠＋外側リング
- **登場アニメーション**：タップ時に scale 1→1.18→0.94→1（0.5s）＋白い霞が広がって消えるバースト演出。`prefers-reduced-motion` 時はアニメーション無効
- スマホ帯では選択したカードを `scrollIntoView({inline:'center'})` で中央に寄せる

## 5. 会話の進行仕様

1. **初期状態**：大番頭のメッセージ「おはようございます、◯◯さん。あなたはどの番頭さんにお願いしたいですか？右（下）からお選びください。」を表示。**入力欄は無効化**（placeholder「番頭さんを選んでからどうぞ」）
2. **カード選択時**：
   - 登場アニメーション＋選択音声を再生（§8）
   - 選ばれた番頭がタイピング演出（0.5秒）→名乗りメッセージ（音声と同文を吹き出しにも必ず表示）
   - 入力欄を有効化。placeholderを「◯◯番頭さんに伝える」に変更
3. **番頭の切り替え時**：システム行「→ 大番頭が『◯◯』から『◯◯』へお取り次ぎしました」を中央寄せ・小さめ文字で挟む
4. **依頼中（API処理中）**：選択中の番頭のタイピング演出＋「◯◯番頭が考えています…」。**入力データは処理開始前にDB保存済み**であること（失敗しても入力が消えない）
5. **仕事完了時**：完了音声を再生（§8）＋成果物カード（プレビュー＋「これで貼り出す」「直してもらう」ボタン）をチャット内に表示
6. **エラー時**：「◯◯番頭が席を外しているようです。書いた内容は残っていますので、もう一度お試しください。」＋再試行ボタン。朱色は枠線程度に留める
7. 各番頭の名乗り・完了セリフは `lib/bantou.ts` に一元定義（音声ファイル名・帯色・名前・絵文字とセットの定数オブジェクト）

## 6. リレー方式（次の番頭さん提案）の仕様

### 基本ルール

1. 番頭の仕事が1つ完了するたび、**次に役立つ番頭を最大1人だけ**提案する（一度に複数提案しない。選ばせる負荷を作らない）
2. 提案はチャット内で、次の番頭本人が登場して一言＋**「お願いする／今はいいです」の2択ボタン**で行う
3. 「今はいいです」を選んだ提案は、**同じセッション内では再提案しない**
4. 「お願いする」を選ぶと、その番頭が選択状態になる（カードの選択と同じ処理を通す。アニメーション・音声も同様に再生）
5. リレーの定義は `lib/relay.ts` に対応表として一元管理する（コードにif文を散らばらせない）

```
形式イメージ：
{ from: 'hari', trigger: 'done', to: 'koyo',
  message: '暦番頭です。この掲示、いつまで貼っておきますか？期限を決めておけば、下げ時をお声がけしますよ。',
  phase: 1 },
```

### リレーパターン一覧

**パターン①：お知らせ一式リレー（Phase 1の主線）**
```
はり出し（作成完了）
 → 暦「この掲示、いつまで貼っておきますか？」（期限設定）
 → （期限到来時）暦「そろそろ下げ時です。新しいお知らせを作りますか？」→ はり出しへ戻る
```
Phase 1で実装するのはこのパターンのみ。鮮度管理（課題④）がこのループで回り始める。

**パターン②：議事録リレー（Phase 2）**
```
筆どめ（議事録完成）
 → はり出し「決まったことを、お知らせとして貼り出しましょうか？」
 → 暦（期限設定・①に合流）
```
議事録→掲示のワンタップ連携（要件定義書の機能③）をリレーとして表現する。

**パターン③：先回りリレー（暦番頭起点・Phase 2）**
```
暦（季節・行事の提案：「もうすぐ防災訓練の時期では？」）
 → はり出し「案内をお作りしましょうか？」
 → 暦（期限設定・①に合流）
```
ユーザーの操作なしに暦番頭がホーム表示時に話しかける唯一のパターン。**1日1回まで**に制限（うるさくしない）。

**パターン④：蔵からの再利用リレー（Phase 2）**
```
蔵（過去のお知らせを表示中）
 → はり出し「去年のこの案内を下敷きに、今年の分をお作りしましょうか？」
 → 暦（期限設定・①に合流）
```
理事交代後の新任理事が最も助かる導線。「前任者のやり方を真似できる」体験。

**パターン⑤：配信リレー（Phase 3）**
```
はり出し（作成完了）
 → 触れ回り「みなさんへの配りもの（メール・画面）も承りましょうか？」
 → 暦（期限設定・①に合流）
```
Phase 3で①の直後に挿入。優先順位は 触れ回り → 暦 の順で1人ずつ提案。

**パターン⑥：緊急リレー（Phase 3・唯一の自動連続実行）**
```
火消し（緊急モード起動）
 → 触れ回りが自動で一斉連絡（※提案を挟まず即実行。緊急時に2択を出さない）
 → （解除後）はり出し「復旧のお知らせを作りましょうか？」
 → 蔵（対応記録として自動収蔵）
```
緊急時のみ「提案→承諾」を省略する。平時のリレーとは明確に区別すること。

### 競合時の優先順位

同じ完了イベントに複数のリレー候補がある場合（Phase 3以降）：**触れ回り（配信）＞ 暦（期限）＞ その他** の順で1人だけ提案し、承諾・辞退の後に次の候補を提案する。

### 全パターン共通の終点

すべてのお知らせ・議事録は完了時に**蔵番頭へ自動で収蔵される（提案不要・無言で実行）**。チャットに「蔵に納めました」等をいちいち表示しない（うるさいため）。蔵番頭を選んだときに見えていればよい。



| ID | 名前 | 帯色 | 絵文字（仮） | 役割 |
|---|---|---|---|---|
| oo | 大番頭 | ai | 🙂 | 取り次ぎ・初期案内 |
| hari | はり出し番頭 | hari | 📜 | お知らせ作成（Phase 1で実処理あり） |
| fude | 筆どめ番頭 | fude | 🖋️ | 議事録（Phase 2まで「この秋から承ります」と応答） |
| fure | 触れ回り番頭 | fure | 📣 | 配信（Phase 3まで準備中応答） |
| koyo | 暦番頭 | koyo | 📅 | 時期・鮮度アラート |
| hike | 火消し番頭 | hike | 🔔 | 緊急（Phase 3まで準備中応答） |
| kura | 蔵番頭 | kura | 🗄️ | 過去のお知らせ一覧表示 |

Phase 1で実処理があるのは **hari（生成）と kura（一覧）** のみ。他は世界観を壊さない「準備中」の応答を返す。

## 8. 音声再生仕様

### ファイル
- 置き場所：`public/sounds/`
- ファイル名：`{番頭ID}_{場面}.mp3`（例 `hari_select.mp3` `hari_done.mp3`）。一覧は台本（bantou-voice-script.md）と完全一致させること
- 大番頭用：`oo_welcome.mp3`（初回表示時ではなく**最初のユーザー操作後**に再生。※ブラウザは操作前の自動再生を禁止しているため）、`oo_handoff.mp3`（切り替え時）

### 再生ロジック（lib/sound.ts として実装）
```
- Audioオブジェクトは番頭ID+場面をキーに使い回す（毎回newしない）
- play(bantouId, scene) を公開。再生前に必ず現在再生中の音を停止（セリフの重なり禁止）
- 音量は 0.8 固定
- ミュート状態は localStorage('bantou-muted') に保存し、次回起動時も引き継ぐ
- ミュート中は play() が何もしない
- 再生失敗（ファイル欠落・ブラウザ制限）は console.warn に留め、UIは絶対に止めない
```

### 再生タイミング
| タイミング | 音声 |
|---|---|
| 番頭カードをタップ | `{id}_select.mp3`（登場アニメーションと同時） |
| 生成・処理が完了して成果物カードを表示 | `{id}_done.mp3` |
| 番頭の切り替え | `oo_handoff.mp3` → 続けて新しい番頭の select |

### アクセシビリティ原則
- **音声で伝える内容は必ず同じ文言を吹き出しにも表示する**（音を切っても体験が完結すること）
- ヘッダーの🔊ボタンはaria-label「音を消す／音を出す」を付与

## 9. 実装しない・やらないこと

- チャット履歴の永続化（Phase 1ではページリロードで会話は消えてよい。生成したお知らせ自体はDBに保存されるため失われない）
- 自由入力からの番頭自動振り分け（大番頭のAI取り次ぎはPhase 2。Phase 1では未選択時の入力は無効化で対応）
- 音声の動的生成（TTS APIは使わない。事前生成したmp3のみ）
